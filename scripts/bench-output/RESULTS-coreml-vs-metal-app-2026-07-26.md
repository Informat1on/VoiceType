# CoreML/ANE против Metal + tensor API — замер в сценарии приложения (2026-07-26)

**Вывод: на M5 Pro в том сценарии, в котором работает VoiceType, CoreML/ANE быстрее
Metal + tensor API на 12–20%.** Это опровергает вывод замеров от 2026-07-26 (утро),
зафиксированных в `RESULTS-m5-backend-2026-07-26.md`.

## Числа

Машина: M5 Pro. Модель: `large-v3-turbo-q5_0`. Язык `ru`, 4 потока, greedy.
Модель загружается **один раз**, первый прогон отбрасывается как прогрев,
дальше медиана. Меряется только `transcribe()`, без загрузки модели.

| Аудио | CoreML / ANE | Metal + tensor | Разница |
|---|---:|---:|---|
| 5.4 с (`Tests/Fixtures/bench/02.wav`) | **192 мс** | 231 мс | CoreML быстрее на 20% |
| 81 с (`live-20260427-185032/recording.wav`) | **1209 мс** | 1359 мс | CoreML быстрее на 12% |

Сырые прогоны, 5.4 с: CoreML 443 / 192 / 193 / 190; Metal 245 / 231 / 232 / 228.
Сырые прогоны, 81 с: CoreML 1443 / 1209 / 1203; Metal 1363 / 1355 / 1359.

Корректность сравнения подтверждена логами whisper в том же прогоне:
в первом случае `whisper_init_state: Core ML model loaded`, во втором —
`failed to load Core ML model from '.../.metal-only/...'` при `has tensor = true`.

## Почему утренний замер показал обратное

Утром мерили `whisper-cli`, который **загружает модель при каждом запуске**, и брали
`total time`. Загрузка `.mlmodelc` в Neural Engine стоит ~250–435 мс и целиком попадала
в эту метрику.

Признак был виден уже в тех данных: разница «с CoreML» − «без CoreML» составляла
435 мс на 5.4-секундном аудио и 379 мс на 90-секундном — почти одинаково, при том что
сам энкодер давал лишь 112 мс. Фиксированная, не зависящая от длины записи разница —
это оверхед инициализации, а не скорость инференса.

Виден он и в этом замере напрямую: у CoreML первый прогон 443 мс против последующих
190 (разогрев ANE ~250 мс), у Metal 245 против 230 (разогрева почти нет).

## Почему в приложении это не важно

VoiceType держит модель загруженной в памяти (`TranscriptionService` — синглтон) и
прогревает её через `performWarmUp()` — 500 мс тишины сразу после загрузки. Разовый
разогрев ANE поглощается прогревом и пользователю не виден ни разу. Значение имеет
только установившаяся скорость, а она у CoreML выше.

## Что осталось верным из утренних замеров

Сравнение самих Metal-конфигураций между собой не затронуто: tensor API действительно
почти вдвое ускоряет энкодер относительно Metal без него (encode 1213 → 612 мс).
Неверен только вывод, что этого достаточно, чтобы обогнать ANE.

## Следствие для политики

`AccelerationPolicyResolver`: режим `auto` использует CoreML везде, где он установлен,
включая чипы с tensor API. Metal-only остаётся осознанным ручным выбором и штатным
запасным вариантом, когда энкодера нет.

## Как воспроизвести

Бенчмарк — отдельный пакет, зависящий от форка SwiftWhisper напрямую; он грузит одну и
ту же модель двумя путями (обычный и через `Models/.metal-only/`) и меряет `transcribe()`
на одном и том же аудио. Исходник: `session2-artifacts/bench-coreml-vs-metal/`.
