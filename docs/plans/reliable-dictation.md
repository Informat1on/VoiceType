# Этап 1 — надёжная диктовка: буфер обмена, адресат вставки, честный таймаут, восстановление

Дата: 2026-09-23. Ветка: `feat/reliable-dictation`. Источник приоритетов — внешний разбор
GPT-6 Astra (`~/.pi-runs/20260923-224349-94115.result.md`) и сравнение с klava-nevinovata.

## 1. Цель

Сказанное не теряется и попадает туда, куда пользователь диктовал: вставка через paste
больше не уничтожает содержимое буфера обмена (картинки, файлы, RTF), текст не уходит
в приложение, на которое пользователь переключился во время распознавания, сбой ASR
оставляет запись с аудио и кнопкой повторного распознавания, таймаут ASR действительно
срабатывает, следующую диктовку можно начать сразу после вставки.

**Главное ограничение — никакой деградации**: модель, промпт, пост-обработка, режим
Type, правило Claude Code → paste, порядок auto-Enter, путь ошибок Accessibility и
прерывания захвата остаются как есть.

## 3. Решения

- **D1. Буфер обмена.** Полный снимок всех элементов и всех типов перед paste,
  восстановление после, только если `changeCount` всё ещё наш (иначе кто-то скопировал
  новое — не затираем). Наш временный текст помечается `org.nspasteboard.TransientType`
  и `org.nspasteboard.AutoGeneratedType`, чтобы менеджеры буфера (Raycast, Maccy, Paste)
  его не записывали. Снимок снимается вне main с дедлайном 500 мс и потолком 64 МБ;
  если снять полностью не удалось — буфер **не трогаем вообще** и вставляем печатью (Type).
  Консистентность: `changeCount` запоминается до снимка и хранится вместе со снимком; если он
  изменился за время снимка — одна повторная попытка, затем fallback на печать. Непосредственно
  перед `clearContents()` счётчик сверяется ещё раз: не совпал (пользователь скопировал новое
  после снимка) → fallback на печать, буфер не трогаем.
  Снимок читается на фоновой очереди через **отдельный экземпляр** `NSPasteboard(name: .general)`;
  по таймауту результат отбрасывается, фоновое чтение ничего не пишет.
  Задержка перед восстановлением — 150 мс (было 100 мс блокирующим `usleep` на main).
  Порядок как сейчас: paste → пауза → auto-Enter → восстановление.
  Отдельного тумблера «сохранять буфер» нет: терять содержимое буфера не нужно никому.
  Режим «вообще не трогать буфер» уже есть — Paste method = Type; подписи пикера
  переименовываются, чтобы это было видно.
- **D2. Адресат вставки.** Приложение (PID), захваченное при нажатии хоткея, — адресат.
  Если к моменту вставки активно другое приложение — не вставляем, запись остаётся
  в истории с `insertSuccess=false`, капсула «App changed · Saved to History», фокус
  назад не выдёргиваем: `FocusCaptureService.shared.suppressNextRestore()` вызывается до
  показа ошибки, поэтому последующий `hide()` (авто-скрытие errorInline) не активирует A. Если при нажатии хоткея активен сам VoiceType (диктовка в его
  Settings) — проверка не применяется (прежнее поведение).
- **D3. Таймаут ASR.** Гонка без ожидания зависшего дочернего вызова; при таймауте —
  whisper.cpp `abort_callback` + `Whisper.cancel`, экземпляр `Whisper` отбрасывается
  («abandoned run»), модель перезагружается штатно при следующей диктовке. Таймаут =
  `max(30 с, длительность аудио)`, чтобы длинные записи, которые раньше проходили, не обрывались.
  **Владение native-буферами:** всё, на что указывает `whisper_full_params` во время вызова,
  живёт до фактического возврата native-вызова: `_initialPrompt` становится ссылочным
  `NativeCString` (free в deinit), каждый запуск захватывает текущий буфер и `NativeAbortSignal`
  в замыкание операции; замена промпта освобождает буфер только после возврата всех
  запусков, которые его держат. Язык (`WhisperParams.language`) принадлежит экземпляру
  `Whisper`, его удерживает замыкание форка.
  **Прогрев:** обычный путь не меняется (реальная диктовка ждёт окончания прогрева как
  сейчас), но ожидание ограничено 10 с; внутренний таймаут прогрева (30 с) становится
  настоящим через ту же гонку. Истёк любой из них → abort + abandon + `.notLoaded`.
  **Shutdown:** ожидание прогрева ограничено; при наличии abandoned-запусков, ещё не
  вернувшихся, `shutdown()` возвращает `false` (вызывающий уходит через `_exit`, как сейчас
  при затянувшейся транскрипции).
  **Эксклюзивность:** `transcribe` захватывает `isTranscribing` до первого `await`;
  параллельный вызов получает новый `TranscriptionError.busy`, а не `instanceBusy` форка.
  **Повторная проверка экземпляра:** после ожидания прогрева `transcribe` заново читает
  `self.whisper` и поколение модели; ASR никогда не запускается на экземпляре, захваченном
  до `await`. Отброшен → `TranscriptionError.modelNotLoaded`; AppDelegate на эту ошибку
  один раз вызывает `ensureModelLoaded()` и повторяет `transcribe` с тем же аудио.
  **Инвариант abandoned-запуска:** замыкание операции (владеет `NativeCString` промпта,
  `NativeAbortSignal` и ссылкой на `Whisper`) живёт до фактического возврата
  `whisper.transcribe`; `abandonedRunCount` уменьшается только там. `isTranscribing == false`
  при `abandonedRunCount > 0` не означает безопасный выход — shutdown проверяет оба.
- **D4. Сбой ASR → запись в истории.** Только при ошибке/таймауте ASR (не при пустом
  результате — случайные нажатия не должны вытеснять историю). Запись `status: failed`,
  текст пустой, аудио сохранено; в History — «Retry transcription», повтор не вставляет
  текст, а заполняет запись (дальше обычный Re-insert). `latestEntry()` (Cmd+Opt+E)
  пропускает неуспешные записи. **Хранение:** failed-записи не входят ни в лимит 100
  обычных записей, ни в буфер ротации несохранённого аудио; у них свой лимит — 20
  (старейшая failed удаляется вместе с аудио, только после успешной записи JSONL). После
  успешного повтора запись становится обычной и **перемещается в начало списка** (поле
  `timestamp` не меняется), затем сразу применяется обычный лимит — перемещённая запись
  под вытеснение не попадает. Метод `HistoryStore.promoteRetried(_:)`. **Эксклюзивность повтора:** повтор возможен только при `appState == .idle`;
  на время повтора `appState = .transcribing` (капсула не показывается), поэтому хоткей
  и «Start recording» из меню не стартуют параллельную запись; History открыт из Settings,
  а при открытых Settings хоткей и так выключен.
- **D5. Готовность к следующей диктовке.** `appState = .idle` сразу после завершения
  вставки (включая восстановление буфера), анимация «Inserted» идёт независимо. Отложенные
  скрытия «Inserted» **и** «emptyResult» проверяют ID сессии капсулы перед `hide()`.
  Скрытие `errorInline` уже защищено проверкой состояния (`RecordingWindow.swift:90`,
  `AppDelegate.swift:114`) — не трогаем.
- **D6. Замер пути.** Для каждой диктовки — `latencyMs` в записи истории
  (`stopToSamples`, `asr`, `insert`, `total`), `history-report.py` печатает p50/p95.
- **Вне этапа:** правка форка SwiftWhisper (игнорируется код возврата `whisper_full`),
  координатор-рефакторинг AppDelegate, VAD, стриминг.

## 5. Риски

- Восстановление буфера раньше, чем целевое приложение прочитало его, → вставится старое
  содержимое (теперь это может быть картинка). Митигация: 150 мс ≥ прежних 100 мс, которые
  в эксплуатации не давали такого эффекта на строках.
- Чтение pasteboard вне main: при таймауте буфер не трогаем, параллельной записи нет.
- D2 меняет поведение: при сознательном переключении во время распознавания текст не
  вставится, а останется в истории. Это намеренно (иначе, с auto-Enter, сообщение уходит
  в чужой чат).
- После таймаута два контекста whisper в памяти, пока отброшенный не вернётся (с abort —
  быстро).
- Сбой ASR при ошибке whisper.cpp форк маскирует как успех с пустым текстом (код возврата
  игнорируется) — такие случаи остаются «пустым результатом», не failed. Вне этапа.

## 7. Ручной чек-лист (после установки сборки)

1. Скопировать картинку → продиктовать в TextEdit, Slack, Claude Code → картинка по-прежнему в буфере (Cmd+V в Preview).
2. Скопировать файл в Finder → продиктовать → Cmd+V в Finder копирует файл.
3. Менеджер буфера не показывает продиктованный текст отдельной записью.
4. Начать диктовку в редакторе, во время «Transcribing» переключиться в другое приложение → текст не вставлен, запись в History.
5. Две диктовки подряд сразу после «Inserted» — вторая стартует без задержки, капсула не пропадает.
6. Сбой ASR (`open --env VOICETYPE_DEBUG_FAIL_ASR=1 …`) → «Saved to History» → Retry transcription → текст в записи.
7. Режим Type, auto-Enter, Cmd+Opt+E — работают как раньше.
8. Во время вставки (сразу после отпускания хоткея) скопировать что-то новое → новое содержимое не затёрто.
9. Переключение приложения во время распознавания при включённом auto-Enter → ни текста, ни Enter в чужом окне.
10. Ошибка Accessibility (снять галочку) → прежнее сообщение и открытие настроек; прерывание захвата (выдернуть микрофон) → прежнее поведение.
