# Корпус `eval-ru` — оценка постобработки транскрипта

Не путать с `Tests/Fixtures/bench/`. У корпусов разные цели и **несовместимые
эталоны**, и это осознанно:

| | `bench/` | `eval-ru/` (этот) |
|---|---|---|
| Что мерит | точность ASR (WER) | качество постобработки по категориям |
| Эталон | дословная расшифровка речи, числа словами | текст по конвенции, числа цифрами |
| Речь | скриптованные фразы | реальная рабочая диктовка |
| Метрика | `scripts/wer.py` | `scripts/categorized-eval.py` |

Эталоны `bench/` для постобработки не годятся: их README называет тексты «exact
reference text», числа в них записаны словами, тогда как конвенция требует цифр
для чисел больше десяти. То есть эталон прямо конфликтует с целью задачи. Оба
корпуса остаются, каждый для своей метрики.

Конвенция целевого выхода: `docs/decisions/2026-07-27-transcript-postprocessing-convention.md`.

## Что в репозитории и чего в нём нет

**Коммитится:** `manifest.jsonl`, `schema.json`, этот файл.

**Не коммитится** (`data/` в `.gitignore`): аудио и тексты. Это реальная рабочая
речь владельца, а репозиторий публичный. Решение владельца 2026-07-27:
метаданные в репозиторий, речь остаётся локально.

Следствие, которое надо знать: **метрика не воспроизводима на CI и у сторонних
контрибьюторов.** Она воспроизводима только на машине владельца. `manifest.jsonl`
фиксирует состав и разбиение, чтобы результаты прогонов были сравнимы между собой,
но не чтобы кто-то другой мог их повторить.

## Структура `data/`

На каждую запись `NN` (01–41):

| Файл | Что |
|---|---|
| `NN.wav` | аудио, 16 кГц моно Int16 — родной формат whisper, сконвертировано из `.caf` без пересемплирования |
| `NN.raw.txt` | сырой вывод whisper, взят из `history.jsonl` как есть |
| `NN.ref.txt` | эталон по конвенции |
| `NN.spans.json` | разметка спанов по категориям, см. `schema.json` |

## Как отобраны записи

Источник — `~/Library/Application Support/VoiceType/history.jsonl` на машине
владельца, все 100 записей имели живое аудио. Отбор **стратифицированный, не
случайный**, и правило зафиксировано здесь, потому что постфактум его не
восстановить, а без него прогоны несравнимы.

1. Сначала включены **все** записи, содержащие редкие целевые категории
   (`handoff`, `doubling`, `anglicism-verb`, `propn`) — 36 записей.
2. Затем добивка по длине до покрытия всех интервалов — ещё 5 записей.

Итог: 41 запись, 1152 секунды (19 минут) аудио.

| Длина, символов | Записей |
|---|---:|
| < 80 | 8 |
| 80–200 | 14 |
| 200–500 | 10 |
| 500–1200 | 7 |
| ≥ 1200 | 2 |

| Категория | Записей |
|---|---:|
| `filler` | 23 |
| `propn` | 21 |
| `handoff` | 12 |
| `anglicism-verb` | 11 |
| `number-digit` | 5 |
| `number-word` | 4 |
| `doubling` | 1 |

## Разбиение dev / holdout

Поле `holdout` в манифесте: 9 записей holdout, 32 dev. Разбиение
детерминированное (по SHA-1 от `sourceId`), то есть воспроизводимое и не
подстраиваемое.

**Зачем.** Черновые эталоны готовит тот же агент, который затем пишет правила
нормализатора и мерит его качество. Это создаёт риск подгонки правил под корпус.
Holdout не используется при составлении словаря и правил — только в финальном
прогоне. Результаты показываются раздельно: dev и holdout.

Замечание код-ревью, из которого это выросло: слепая вычитка эталонов владельцем
проверяет качество разметки, но не защищает нормализатор от переобучения на тест.

⚠️ **Что этот holdout доказывает, а что нет** (уточнение 2026-07-27 по замечанию
код-ревью). Он **не** доказывает генерализацию: `eval-ru` отобран из тех же 100
записей `history.jsonl`, которые вошли в корпус на 1096 записей, откуда выведены
конвенция и словарь. Формы holdout могли попасть в словарь ещё на этапе конвенции.

Он доказывает более узкое, но полезное: имплементатор не подгонял правила под
видимые эталоны, потому что этих девяти записей не видел. Именно так он и сработал
в первом же прогоне нормализатора — вскрыл неверное исправление (`Клод-код` →
`Claude-код` вместо `Claude Code`), которого dev не показывал.

Настоящий независимый holdout возможен из переразмеченного архива аудио, но тот
снят с bilingual-seed промптом, которого в проде нет, поэтому его тексты не
сопоставимы с продовыми. Это отдельная задача.

⚠️ **Для конвейера `n2` holdout уже не является независимой оценкой**
(2026-07-27). При разработке правила удаления филлеров его ошибки на holdout
были просмотрены, и хотя уточнение правила («удалять только строчные») выведено
из dev-данных, факт просмотра делает оценку смещённой. Дальше этот split — набор
для отлова регрессий, а не мера обобщения.

Замена ему на время: выборочный аудит удалений на продовом корпусе
(`scripts/filler-audit.py`, 216 случаев из 1541, стратификация по словам,
фиксированный seed). Он даёт настоящий доверительный интервал вместо оценки по
четырём наблюдениям, но требует ручной разметки владельцем и остаётся локальным
файлом — речь в git не уходит.

## Границы применимости

- **Категории `doubling` (1 запись) и `number-word` (4) покрыты плохо.** На полном
  корпусе из 1096 записей они частотны (пропущенное удвоение около 40 вхождений,
  числа словами 409), но здешние 100 записей — срез всего за четыре дня 24–27 июля,
  остальное вытеснено rolling-капом истории. Для этих категорий корпус нужно
  расширять аудио с рабочей машины владельца.
- **Стратификация искажает естественную частоту категорий.** Это правильно для
  метрики по категориям, но общий «средний fix rate продукта» по этому корпусу
  считать нельзя без взвешивания частотами из документа конвенции.
- **Одна машина, одна модель, один микрофон** (`large-v3-turbo-q5_0`, M5 Pro).
- Для редких категорий метрика обязана показывать абсолютные `x/n`, а не проценты:
  при 8–12 вхождениях один пример сдвигает процент на 8–12 пунктов.
